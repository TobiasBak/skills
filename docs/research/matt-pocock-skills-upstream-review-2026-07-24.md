# Matt Pocock skills upstream review

Research date: 2026-07-24

## Final approved decision

The final vendored allowlist is exactly:

- `batch-grill-me`
- `grill-with-docs`
- `handoff`
- `to-spec`
- `to-tickets`

This supersedes the pre-decision recommendations below, including the recommendation not to admit `batch-grill-me`. The selected set keeps the differentiated interactive and handoff workflows plus the two planning-artifact workflows. `batch-grill-me` was admitted because asking the whole unblocked decision frontier reduces interaction latency while preserving dependency order; `grill-with-docs` now routes to it. `to-spec` and `to-tickets` use explicit repository or user tracker configuration when available and otherwise write simple local files, without depending on `setup-matt-pocock-skills` or inventing labels.

The other previously vendored skills were pruned because they were Matt-specific, unsafe or side-effectful for this workbench, redundant with normal agent/repository behavior or retained personal skills, or not valuable enough to justify permanent catalog and maintenance surface. The updater now encodes these five paths as an explicit allowlist, preserves local OpenAI metadata, validates local overlays before replacement, and cannot admit future upstream skills through discovery.

## Superseded recommendations from the research phase

These recommendations record the evidence-to-decision path and are not the current admission or updater policy. The final decision above controls where they conflict.

1. **Do not sync with the updater as it existed during research.** Closest rejected alternative: run it and reconstruct overlays from the diff. That gained five behavior updates quickly but created avoidable risk because committed overlays were not guarded and upstream metadata disabled the preservation branch.
2. **Before a future sync, encode ownership explicitly:** preserve local `agents/openai.yaml` unconditionally or reapply a maintained metadata overlay; reapply the local domain-modeling, research, grilling, and prototype changes; keep both writing patches. Then test the updater in a disposable clone and review its diff without installing.
3. **Selectively port four upstream ideas:** architecture scan scoping; generalized grilling wording; per-ticket local files plus cleanup; “decision ticket” terminology. Review wayfinder's parallel research dispatch separately. Reject prototype branch preservation.
4. **Admit no new skill now.** Watch `batch-grill-me`; consider `setup-ts-deep-modules` only for a repository with a demonstrated TypeScript package-boundary failure. Everything else is Matt-specific, deprecated, redundant, narrow, or still in progress.
5. **Update the local PR 522 wording when updater work is authorized.** PR 522 did not land, but its essential metadata approach did via PR 551. The durable local question is no longer “has PR 522 landed?” but “which fields and invocation choices are upstream-owned versus local overlays?”
